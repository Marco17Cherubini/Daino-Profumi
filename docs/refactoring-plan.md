### Decisions taken during execution

- **Custom elements instead of a home-made component registry** (ADR-002). The lifecycle comes from the browser, and it also covers Theme Editor re-renders.
- **Initial variant resolved in Liquid**, not JavaScript. `?variant=` is respected, there is no price flash, and it works without JS.
- **Native links** for filter tag removal, reset and cart line removal (`url_to_remove`). They work without JavaScript and remove the price range correctly.
- **Narrative and consulenza text** made editable, with defaults identical to the old hard-coded text.
- **Footer setting defaults aligned** with the old hard-coded text, so stores that never saved settings render exactly as before.
- **Missing CSS tokens defined** (ADR-011). This is a visible correction on pages that rendered without their intended styles.
- **GSAP re-attachment guard.** The tests showed that GSAP temporarily re-parents fixed elements while measuring them. The gate and the carousel ignore those transient moves.
- **Price filter changes are debounced.** Leaving a price field no longer fires an extra request (found by a DOM test).

### New defects found and fixed

See ADR-014: the `push` filter, the `policies` object, the password recovery flow, the province selector, unstyled customer pages, the password page logo setting, and focus in the search overlay.

### Separate proposals (out of scope, not started)

- A real navigation menu (desktop and mobile). The dead drawer was removed, as you decided.
- Move the 18 MB hero video to Shopify Files or a `video` setting, and add `preload="metadata"`.
- Cart drawer and AJAX quantity updates.
- Visible scrollbars (currently hidden site-wide, which is a design choice).
- Brand carousel on the product page via search or filters instead of the first 50 products of `all`.
- Payment icons from `shop.enabled_payment_types` instead of four fixed brands.
- Section groups for header and footer (changes how the merchant edits them).
- `fetchpriority="high"` is still applied to the first 9 collection images, as before. Reducing it to the real above-the-fold images is worth measuring.

# Approved plan

## Context

The aim is to turn the Daino-Profumi theme into a reliable, maintainable project that can be verified and shown in a portfolio. Lev Space is the reference for order and verifiability. The identity, content and purchase paths stay the same.

**Starting state (checked):**

- The repo is on `main` at `2930d82`, with a clean working tree and only 2 commits ("Initial commit", "Add files via upload").
- There is no CLAUDE.md, no package.json, no tests, no CI and no lint configuration.
- The theme lives in `DainoTheme_official - Claudio 1 banner/`, a folder name with spaces.
- About 330 KB of Liquid, CSS and JS, plus about 21 MB of media. The 18 MB `Video Project 2.mp4` is included in that.
- Available locally: Node 22, npm, a global prettier, and Chromium with Playwright. Not available: Shopify CLI and Theme Check.
- There is no access to a Shopify store or preview from this session.

**Lev Space was read-only accessible** (README, configs and file tree through GitHub).

**Your decisions (already taken):**

- Theme moves to the repo root.
- "Acquista ora" becomes add-to-cart followed by checkout.
- The dead mobile drawer is removed. A real menu becomes a separate proposal.
- Create both the `legal-hub` section and the search page.

### Key decisions (to be recorded as ADRs in `docs/decisions.md`)

1. **JS without a bundler: IIFE files that register on `window.Daino`, with a CommonJS export guard for tests.**
   - Alternatives considered: native ES modules (asset imports need versioned CDN URLs, which is fragile in Liquid), or a bundler such as esbuild (adds a build step and a gap between source and deployed theme).
   - Advantage: the deployed files are the source files, and the logic can be tested directly in Node.
   - Trade-off: ordering is managed through `defer`.
2. **Component lifecycle.** `Daino.components.register('product-form', root => { …; return destroy; })` is applied to `[data-component]` and wired to `shopify:section:load` and `shopify:section:unload`.
   - Advantage: repeatable initialisation, no duplicated listeners, multiple instances supported.
   - Trade-off: a small convention every component has to follow.
3. **Liquid → JS data** goes only through `<script type="application/json">` with `| json`: variants, routes, `money_format`, translated strings. No string interpolation inside JS.
4. **Scroll.** A single owner, `Daino.scrollLock` (reference-counted), which also stops and starts Lenis. `normalizeScroll` is removed.
   - Trade-off: desktop scroll feel needs to be confirmed in a preview.
5. **Server-rendered cards** (one snippet). JS-rendered cards (wishlist) use a `<template>` produced by the same snippet.
   - Advantage: one markup source, correct money and escaping.
6. **Section rendering** for filters and search results, without parallel JSON APIs.
7. **Self-hosted animation libraries**, same versions, with `defer`.
   - Alternative: CDN with SRI.
   - Advantage: no third-party origins, served from Shopify's CDN.
   - Trade-off: about 100 KB of vendor files in the repo.

### Behaviour to preserve

- Section types, block types and setting IDs: unchanged.
- The wishlist `localStorage` key and its format (array of IDs): unchanged.
- URLs and the filter parameters `filter.*`: unchanged.
- Visuals: the gate, the brand marquee, the 3D carousel, the zig-zag consulenza layout, the narrative section, the gold/black palette and the fonts.
- The cheapest variant is selected by default when the URL has no variant.

### Compatibility and migration

- Only additions are made to the JSON templates, apart from removing the inert section groups.
- New settings have defaults that reproduce today's behaviour.
- **Risk:** the live theme's JSON may differ from the repo, because editor changes are not in git. Before any publish: `shopify theme pull --only templates/*.json --only config/settings_data.json` into a separate folder, then diff. This is documented in `docs/testing.md` and is left to you, because there is no access to the store from here.
